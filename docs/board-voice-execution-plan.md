# VelaGuard 板端自然语言语音交互执行方案

日期：2026-10-20。状态：设计已获用户确认；本文件是任务拆分，功能实现和验收尚未完成。架构决策见 [ADR 0009](adr/0009-board-push-to-talk-voice.md)。

## 1. 目标与范围

用户在任意普通页面按住开发板 USER1 说话，松开后自动提交。板载麦克风采集语音，经云侧 ASR 转成文字，由板载 ai_agent 调用只读工具查询现场数据；回答在跨页面浮层显示，经云侧 TTS 生成音频，从板上 Line Out 输出。

首版只支持三个查询意图：当前异常、指定测点读数、告警是否恢复。先验收普通话和 UPS、点位 ID 等必要英文术语。不扩展自由原因分析、预测、配置操作、告警清除或数字量控制。手机直连 MiMo 仍是独立后续目标，见 ADR 0008，本轮不开发手机入口。

本轮新增板端录音、播放和按键驱动集成，替代此前全局不做板端音频的范围限制；不增加持续唤醒监听、离线 ASR/TTS 或主动声音告警。现有后台告警解释和定时报告保留其职责，不能将语音限制误施加到这些后台任务。

## 2. 已确认交互合同

| 项目 | 行为 |
|---|---|
| 发起 | USER1 按下开始录音，松开提交；15 秒上限自动提交；达到上限后等按键释放才接受下一次按下 |
| 接收反馈 | 按键受理后显示录音状态与倒计时；识别后显示文本，自动查询；空识别不发 Agent 请求 |
| 打断 | 播报时按键先停止播放再录音；等待时再次按键取消旧问题并录新问题；旧结果不覆盖或播报 |
| 忙与排队 | 不强行打断正在执行的后台任务；最多一个待处理用户问题，优先于未开始的后台任务；用户再次按键明确替换自己的旧问题 |
| 页面 | 不新增语音页；公共浮层显示状态、文本、回答和错误；普通页面切换保留会话 |
| 显示 | 播报结束后保留回答 15 秒再收起；静音时自显示起计时；滚动阅读暂停计时；收起不结束上下文 |
| 上下文 | 最近明确点位 ID 可用于追问，每次重新取数；主动结束或空闲两分钟清空；录音、查询、播报期间不算空闲 |
| 歧义 | 提示重新报点位 ID 或完整匹配名称；不提供序号选择，不猜测，不以多匹配结果中的第一项代替确认 |
| 输出 | 文字与播报来自同一份已校验结果；异常先报总数及前三项，完整列表在浮层滚动；严重告警优先，其次离线、过期 |
| 查询范围 | 异常包含当前规则告警、离线、数据过期；恢复只覆盖本次上电且仍保留的事件，缺记录明确无法确认 |
| 截止时间 | 松开或15秒自动提交起算，识别、排队、Agent、TTS至首次可播放音频合计最多30秒；静音时以最终文字可见为终点；录音和后续播报时长不计入 |
| 故障 | ASR失败提示重录；模型失败提供显式重试；TTS失败保留文字，仅重试播报；不自动重跑整轮 |
| 播报开关 | 本地持久化，重启后保持；关闭时跳过TTS，文字继续显示；停止当前播报与持久开关分开 |
| 告警 | 按当前程序行为，新告警不抢占语音、不跳页；仅预留统一中断接口，不默认连接到告警事件 |
| 数据保留 | 原始录音只供当次识别，成功、失败、取消后释放；完整对话仅在当前会话内保留；诊断仅存编号、阶段耗时、状态及工具摘要 |

未确定的实现参数由对应任务测量后固化：音频采样率/格式、缓冲尺寸、线程栈、云接口及并发预算。它们不是额外的已实现功能。

## 3. 当前基础与缺口

只读资料核对：官方 Audio.SchDoc 显示 IMP34DT05TR 数字麦克风和 WM8994，ST BSP 提供录音/播放参考。官方 B1 USER 按键为 PC13；现有 board.h 的部分旧注释与原理图冲突，不能按旧注释配置。用户指定 USER1 与实物丝印的对应关系须在 BVO-01 记录。

当前核查的 NuttX 配置未启用 AUDIO、DRIVERS_AUDIO、I2S、INPUT_BUTTONS；已有 wm8994 驱动只声明输出能力，板级音频和按键初始化缺失。录音可能需要独立数字麦克风接收路径，不预设由 wm8994 输入完成。Line Out 的实际接口、路由、电平与外接负载在 BVO-01 核实，不把耳机或扬声器接口名称直接等同于用户要求的 Line Out。

应用已有 vg_point_read、vg_run_report、轮次 owner/generation 隔离基础。运行事件环最多32条，通用报告只展示最近8条，不能直接充当完整异常或告警实例查询。现有诊断回复缓冲仅适合短摘要，不能作为产品完整回答通道。现有轮次超时不能视为已经具备真实网络取消。

这些是源码和资料结论，不代替真机能力证明。实施起点必须重新核对各仓 HEAD、配置、实际固件及未提交改动；不能使用本方案编写时的目录位置替代版本记录。

## 4. 架构与资源边界

```text
USER1 → 按键事件 → 语音会话状态机 → 录音缓冲 → ASR
                                      ↓               ↓
                               跨页面LVGL浮层 ← 识别文本
                                                      ↓
                                    用户请求调度 → 板载ai_agent
                                                      ↓
                              点值 / 当前异常 / 告警恢复只读工具
                                                      ↓
                                结果校验 → 文字浮层 → TTS → Line Out
```

按键中断只投递事件；音频中断/DMA回调只维护有界缓冲和状态。录音、网络、模型、文件、解码均不在 LVGL 线程或中断内阻塞执行。UI 只读取已发布快照，通过消息请求后端操作。

录音与播放互斥。新录音前等待播放设备真正停止，并释放音频缓冲。一个物理网络请求尚未回收时，不把逻辑取消当作可无限创建新请求的理由。采用 session_id、generation、request_id 和 owner 绑定结果；取消、结束会话、重启后旧结果全部失效。

复用确定性数据源，不让语音工具触发新RS485扫描或修改点表。上下文只保存确认的点位身份、必要对话和限定历史；配置版本改变、点位删除或重启时必须失效或重新解析，禁止复用旧读数。

## 6. 数据接口与回答合同

以下是实施草案，字段名可随代码规范调整，语义与边界不能省略。

- 请求：session_id、generation、request_id、提交单调时间、deadline、识别文本、可选明确point_id、配置版本、播放开关。
- 点值结果：point_id、完整名称、数值/单位、online、采样年龄、freshness、数据来源、配置版本；数值未知不使用0填充。
- 异常结果：快照时间、total、items、complete、必要分页信息；每项包含点位、规则等级/离线/过期类别、实测值和已配置阈值。不得直接复用只打印8点的报告并声称全量。多类别重叠按一项点位展开其状态，明确total是异常点位数，避免重复计数。
- 恢复结果：本次启动标识、point_id、告警类型、事件实例或可验证配对标识、触发/恢复时间、当前状态、history_complete/unknown。反复RAISE/CLEAR必须对应同一实例；如果只保留CLEAR而RAISE已淘汰，只报告可证实的恢复事件，不计算缺失起点的持续时长。
- 回答：intent、point_id、display_text、speech_text、结构化事实、状态、数据时间及请求代际。文字完整列表与播报摘要可以长度不同，但事实必须一致；严重异常不可因截断被静默隐藏。

工具侧执行C参数校验、上限、权限、限流和审计。语音会话限定只读工具面，不能借run_shell/read_file/write_file绕过三意图边界；后台受限报告写入保持独立权限。模型文本不直接变为NSH命令。

点位选择：精确ID优先，其次完整名称；同名仍需报ID。ASR将ID识别错误时提示重说，不自动纠正成另一个存在的点位。最近点位上下文只辅助明确的代词追问，不能把一个新的歧义名称强行绑定旧点位。

## 7. 状态机、排队与预算

建议状态：IDLE、RECORDING、ASR、WAIT_AGENT、QUERYING、TTS、PLAYING、RESULT、ERROR，以及内部CANCELLING。逻辑取消立即提升generation并停止展示旧状态；物理资源回收完成前由有界队列管理新请求。

关键规则：

1. 按键抖动不产生新会话；15秒自动提交后持续按住不重复触发。
2. 录音中主动取消/中断丢弃缓冲，不提交半段录音。普通松开表示提交。
3. 新用户问题可替换旧用户问题，不能取消后台日报/告警正在执行的轮次；新问题最多占一个等待槽。
4. 已排队的用户问题优先于未开始后台任务，但保持后台已有合并、限流和退避规则，避免无限堆积。
5. 30秒deadline使用单调时钟，传给所有阶段；每阶段按剩余时间设置截止，不各自领取新的30秒。预算不足时直接结束，内部重试和退避也受剩余预算约束。
6. 取消回收目标先设为发起取消后2秒内完成，并在BVO-07真机验证；若平台无法达到，报告实测并调整实现，不把它当已达标。UI必须及时响应，回收中禁止无限创建请求。
7. 若文字已成功但TTS到期，保留文字并提示播报失败。显式仅重试播报使用新的有界TTS请求，不重新执行Agent或替换已有事实；较旧回答播报时保留其采样时间。
8. 自动收起只影响显示；两分钟空闲结束会话并释放对话。页面切换不重置请求deadline。结束会话、系统停机或预留中断接口均使旧结果失效。

## 8. 音频、内存与凭证

BVO-01输出录音/播放格式和内存上限表。例如16kHz、单声道、16bit PCM的15秒原始音频约480000字节，仅为预算示例，不代表云端接口要求；DMA缓冲、重采样、TLS和模型响应还会额外占内存。需依据板端实际堆和SDRAM布局选方案，验证DMA可达性、缓存一致性、栈余量及缓冲所有权。

优先内存中的有界缓冲或可取消流式发送，禁止无上限累积；如果确需临时文件，必须评估异常清理与重启清理，不能把录音长期留在eMMC。TTS格式须与板端解码器匹配，不预设任意MP3/Opus均可播放。首版录放互斥，不承担全双工回声消除。

Line Out只输出到用户选择的外部播放设备，板端验收记录实际负载和音量；不在本期增加功放或结构安装。USER1按键用途和PC13占用需按原理图+BSP确认后实现。

`connect_info`可用于获准测试或安全provision，禁止提交；不得把完整密钥打印到命令回显、串口、日志、UI或请求抓包。云ASR/TTS的凭证来源和权限在06固化，不把板端密钥写进固件。云端录音/文本保留政策需官方核验，不能用本地释放承诺代替云端删除承诺。

## 9. 验收矩阵与通过条件

| 类别 | 最低测试内容 | 判定 |
|---|---|---|
| 阶段A音频 | 按放30次；1/5/15秒录音；本地录放20轮；取消/上限10轮 | 无重复提交、无录放重叠、播放停止有效、音频格式正确，采集与UI继续运行 |
| 三意图正确性 | 至少30条固定问法，三类各10条，包含普通话、UPS、ID和完整名称 | 返回事实与同轮快照/事件一致；识别或意图错误单列，不能静默选错点 |
| 歧义和边界 | 多温度点、同名、无此ID、跨配置、离线、过期、事件淘汰、重启 | 不猜测；未知明确说明；旧上下文/旧记录不冒充当前状态 |
| 当前异常 | 0项、1项、超过3项、超过旧报告8项；多状态重叠 | 总数和完整列表正确，播报摘要排序明确，无遗漏或重复计数 |
| 恢复关联 | 触发未恢复、已恢复、重复触发、缺RAISE、缺CLEAR、离线但值正常 | 只依据可追溯事件给出结论；当前正常不等于历史恢复已确认 |
| 生命周期 | 连续按键替换、播报中录音、排队过期、页面切换、手动结束、空闲超时 | 旧轮次不显示/不播报，未回收请求不无限累积 |
