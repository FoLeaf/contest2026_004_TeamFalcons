# ADR 0009：板端按键语音查询

- 日期：2026-10-20
- 状态：用户已确认设计，待实现和验收。
- 依据：本次 grilling 访谈确认的板端自然语言交互方案。

## 决策

在开发板上使用麦克风，USER1按住录音、松开发送，最长15秒。录音经云ASR识别后交给板载ai_agent，结果经云TTS生成语音，从板上Line Out输出。云语音优先验证MiMo，接口能力尚待核实。

首版仅查询当前异常、指定测点读数和告警是否恢复。异常包括规则告警、离线和过期；恢复仅覆盖本次上电仍保留的事件。点位歧义要求用户报ID或完整匹配名称。首版普通话，不增加持续唤醒或离线语音识别。

不新增独立页面，任意普通页可通过按键触发跨页面浮层。支持有限上下文、取消、迟到隔离、静音开关和30秒端到端等待上限；新告警当前不打断语音，仅预留中断接口。

## 与既有决定的关系

本决策明确授权规划板端音频驱动及录放能力，替代此前全局不做板端音频的约束。ADR 0008的手机直连MiMo仍为独立后续目标，不恢复手机语音转交板载ReAct的旧设计。板端语音会使用板载ReAct，与手机目标不是同一入口。

配置人工确认、设备端只读权限和本地安全流程不变。语音不能写寄存器、配置、清告警或控制输出。MQTT不承载AI请求或语音分片。

## 实施与验收

先验收USER1、麦克风采集及Line Out播放的本地闭环，再接云语音、只读数据工具、会话调度与浮层。30秒目标依赖真实的截止时间传播与资源回收，不能仅丢弃UI结果。

详细交互、任务依赖及测试矩阵统一见 [执行方案](../board-voice-execution-plan.md)。本决策不代表音频或云服务已可用，也不关闭QA-04或RSP遗留问题。
