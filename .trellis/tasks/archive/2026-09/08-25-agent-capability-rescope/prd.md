# 重构 Agent 能力场景：运营助手（告警解释 + 日报周报 + 自然语言查数）

> 规划完成，用户已批准（2026-08-29）。本任务只产出文档，不写产品代码。
> 技术设计见 `design.md`，改写清单见 `implement.md`。

## Goal

将板载 Agent 的招牌能力从「485 链路劣化时的故障归因与排障实验」改为 **「运营助手」**：

1. **告警解释**（事件主动）：告警产生后自动拉取上下文并生成可读解释
2. **日报 / 周报**（定时主动）：到点自动汇总运行数据并生成报告
3. **自然语言查实时数据**（交互渠道）：CLI / LVGL 问答，附工具调用，**不作为唯一赛道证据**

并把结论回写 `VelaGuard_项目手册.md`、`VelaGuard_推进方案.md`、`CONTEXT.md`、`README.md`。

## Background

v2 将 Agent 定位为排障实验设计者。该方向存在：可枚举问题交给 LLM、演示 AI 不可见、验收成本高、基建重等问题。

用户明确不希望 Agent 做排障。v3 将 Agent 定位为 **「把已采集的数据讲给人听」**，采集、告警、统计仍由本地确定性逻辑完成。

## Decisions

### D1：主场景 = 告警解释 + 日报/周报；辅场景 = 自然语言查数

- **事件主动**：规则引擎产生告警 → 自动启动告警解释会话
- **定时主动**：每日 / 每周到点 → 自动生运行报告
- **交互查询**：用户自然语言提问 → Agent 调只读工具查实时值后回答（CLI 即可满足交互渠道）

### D2：排障与语义标注均不再作为 Agent 招牌

- 485 故障归因 → 确定性规则库（阶段 2），不依赖网络
- 点表语义化（08-25 旧草案）→ 不纳入 v3
- Agent 不再设计总线实验、不再改探查波特率

### D3：工具集从「Modbus 探测」改为「读状态 / 读历史」

见 `design.md` §2。沙箱硬约束（只读、限流、会话门控、审计）一条不减。

### D4：Skill 替换

- 删除 `rs485_fault_triage.md`
- 新增 `alarm_interpretation.md`、`operations_report.md`（或合并为一个 Skill 两章）
