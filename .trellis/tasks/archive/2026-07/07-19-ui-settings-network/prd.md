# 设计首页设置入口与网络设置页

## Goal

在 480x272 的 VelaGuard 设备触控界面中增加清晰、可发现的设置入口，
让操作员能从首页查看真实网络状态并进入设置页。设置页覆盖项目后续需要的
主要设置类别，但本次只有网络设置可操作，其余类别必须明确显示为未开放，
不能制造已经实现的假象。

## Background

- 当前界面由 `app/velaguard_app/src/vg_ui_home.c` 直接使用 LVGL 构建，
  固定分辨率为 480x272，采用深色工业控制台视觉语言。
- 首页现有右侧“网络”状态固定显示“离线”，没有读取系统接口状态，也没有
  页面导航或设置入口（`vg_ui_home.c:451-468`）。
- 触摸输入已通过 `CONFIG_LVX_VELAGUARD_INPUT_PATH` 初始化；输入设备缺失时，
  首页仍需保持可见，当前实现已支持该降级行为。
- 项目已有 RJ45 Ethernet、DHCP 与链路断开重连底座；驱动通过
  `IFF_RUNNING` 发布真实 carrier，netinit 在链路恢复时重新获取 DHCP。
- 应用 README 仍说明应用层尚无 network manager、MQTT、Wi-Fi 或 OTA；因此
  UI 不能把这些未实现能力显示为可用。
- 项目手册定义的长期网络形态为 RJ45 优先、ESP-01 Wi-Fi 备用，且只允许一个
  活动出口；网络状态需要向 UI 发布。
- 中文字体是裁剪字库。新增可见中文文案必须同步补充 16 px 和 20 px 字库字形。

## Requirements

### R1. 首页状态栏

- 首页顶部区域必须持续显示真实网络状态，而非硬编码“离线”。
- 状态栏布局为左侧品牌、中间网络摘要、右侧设置图标；不在入口旁显示“设置”文字。
- 试验/量产模式与固件版本移入设备身份区域，为网络摘要和图标热区让出宽度。
- 至少区分：无物理链路、正在获取地址、已联网；在线时应展示活动接口或
  IPv4 地址中的关键信息，具体密度在 480x272 上不得挤压品牌与固件信息。
- 状态更新不得阻塞 LVGL/UI 主循环；网络故障不得影响本地采集、告警与首页刷新。
- 语义颜色只能表达真实状态：在线使用产品强调色，连接中或降级使用警告色，
  离线使用普通或弱化文本色。

### R2. 首页设置入口

- 首页提供可触摸的设置入口，并有明确按下/聚焦反馈。
- 首页入口只使用用户提供的设置图标素材，不显示“设置”文字标签；必须提供
  足够大的触摸热区，并通过对象描述或等效机制保留可识别语义。
- 设置入口不得遮挡当前采集、告警和设备身份等核心信息。
- 触摸不可用时，首页监控信息仍正常显示，不崩溃、不阻塞 NSH 救援控制台。

### R3. 设置首页

- 设置首页以适合 480x272 触屏的分组列表呈现项目所需设置类别。
- 网络设置是本次唯一可进入、可操作的类别。
- 设置类别与顺序固定为：网络设置、采集与传感器、告警规则、云端与 MQTT、
  声音、系统、固件更新。
- 其他类别显示为“暂未开放”或同等明确状态，且不可误触进入空白页或执行动作。
- 七个类别在可用内容高度内采用纵向滚动；滚动不能带动页面标题栏或返回入口。
- 设置首页提供一致、可发现的返回首页操作。
- 使用用户提供的 `res/setting.svg` 作为首页入口、`res/settings_ethernet.svg`
  作为 Ethernet 设置视觉、`res/WIFI.svg` 作为 Wi-Fi 未开放视觉；源 SVG 保留，
  构建时使用适合当前 LVGL 配置的可链接资源格式。

### R4. 网络设置页

- 网络设置页只展示和修改当前代码与底层网络栈能够真实支持的能力。
- 页面必须显示 Ethernet 链路状态、地址获取状态和当前 IPv4 地址。
- 页面允许用户在 DHCP 与静态 IPv4 两种模式之间切换。
- 静态 IPv4 模式允许编辑 IPv4 地址、子网掩码、默认网关和首选 DNS；
  DHCP 模式下这些输入必须只读或隐藏，避免制造仍会提交的错觉。
- 点击 IP、掩码、网关或 DNS 字段后进入全屏数字键盘编辑页；输入仅允许
  数字与 `.`，最长 15 个字符，并提供明确的取消与确认操作。
- 单字段确认时校验 IPv4 语法；四项配置满足组合校验后才允许保存应用。
- IPv4 地址、掩码、网关和 DNS 必须在写入前完成格式与组合校验；无效配置
  不得落盘。掩码必须连续，地址不得为网络地址、广播地址、组播地址或未指定地址，
  网关必须与设备地址位于同一子网。
- 保存后必须立即应用，不要求用户重启设备。
- 点击“保存并应用”后显示普通确认：DHCP 模式说明将自动获取地址；静态模式
  展示待应用的地址、掩码、网关和 DNS。用户可取消或确认应用，不使用长按或确认码。
- 应用进行中禁用重复提交和模式切换。
- 保存采用临时文件与原子替换；运行时应用必须由统一网络管理边界协调现有
  netinit 的 DHCP 行为，静态模式在链路重连后不得被 DHCP 覆盖。
- 应用期间显示“正在应用”；成功后显示实际生效的地址。
- 修改操作必须有明确保存/应用结果；写入或运行时应用失败时恢复上一份运行
  配置和配置文件，并显示上下文错误，不能仅打印日志或静默失败。
- Wi-Fi/ESP-01 若展示，只能作为未开放占位，不能伪装扫描、连接或信号强度。
- DHCP 模式使用租约提供的 DNS；静态模式应用用户填写的首选 DNS，以支持
  后续 MQTT、AI Bridge 与 OTA 的域名解析。
- 网络配置属于受保护配置，不得在日志或 UI 中泄露未来可能加入的凭据。

### R5. 导航与生命周期

- 首页、设置首页、网络设置页之间的导航不得重复创建后台刷新定时器。
- 页面切换后，不可再更新已销毁的 LVGL 对象。
- 所有页面保持同一深色主题、同一青色强调色和一致的圆角规则。

### R6. 视觉与交互质量

- Design Read：固定尺寸工业设备设置界面，面向现场操作员，采用状态优先、
  克制且高对比度的 LVGL 产品语言。
- 设计参数：`DESIGN_VARIANCE: 4`、`MOTION_INTENSITY: 2`、
  `VISUAL_DENSITY: 7`。
- 不使用装饰性渐变、外发光、伪玻璃、无语义状态点或网页营销页式卡片墙。
- 交互热区、文本对比度、焦点态和按下态必须适合物理触屏。
- 动效只用于按键反馈或页面状态切换，不添加循环装饰动画。

## Acceptance Criteria

- [ ] AC1: 首页在拔线、已插线但无 IPv4、取得 IPv4 三种情况下显示不同且真实的网络状态。
- [ ] AC2: 网络状态周期更新不阻塞采集、告警、运行时间刷新或 NSH。
- [ ] AC3: 用户能从首页进入设置首页，再进入网络设置页，并能逐级返回。
- [ ] AC4: 设置首页完整展示规划内设置类别；除网络外均明确标记未开放且不可执行。
- [ ] AC5: 网络设置页显示 Ethernet carrier、DHCP/静态模式、地址状态和当前 IPv4 地址。
- [ ] AC6: DHCP 与静态 IPv4（地址、连续掩码、同网段网关、DNS）可确认后保存并立即应用。
- [ ] AC7: 无效输入、文件写入失败或网络系统调用失败时给出可见错误，并恢复原运行配置与原配置文件。
- [ ] AC8: 静态模式经历拔线/插线后仍恢复静态地址，不会被后台 DHCP 覆盖；DHCP 模式仍能自动重新获取租约。
- [ ] AC9: 页面反复切换不会重复创建定时器，不会访问已销毁对象或持续增加 LVGL 对象。
- [ ] AC10: 新增中文文案在 16 px/20 px 字体下无缺字方框，480x272 上无裁切或意外滚动。
- [ ] AC11: 没有触摸输入设备时，应用仍启动并持续显示首页；设置入口不影响降级运行。
- [ ] AC12: 项目静态检查、相关回归检查与 openvela 固件编译通过。

## Out of Scope

- 实现 ESP-01 驱动、Wi-Fi 扫描、SSID/密码连接和双 bearer 自动切换。
- 实现 MQTT、AI Bridge、MiMo、OTA、音频或传感器配置业务。
- 重构全部首页信息架构或改变本地安全循环优先级。
- 在本任务中实现网络之外设置类别的业务逻辑。
